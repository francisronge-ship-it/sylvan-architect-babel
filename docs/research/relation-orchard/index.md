## The Original Problem

Babel's old relation rendering only knew how to draw movement. That made an
open model-authored relation contract visually narrow and theory-biased: the
model could state many kinds of relations, but the interface kept turning the
interesting part back into movement.

## The Open-Contract Dilemma

The renderer cannot enumerate every relation syntacticians may ever name, and
deterministic code should not silently perform new linguistic analysis. The
solution is a layered visual language:

- Tier 1 selects source-backed curated relations by exact registered names.
- Tier 2 recovers independently supported visual claims from authored anchors
  and literal values when the exact relation identity is unknown.
- Tier 3 falls back to neutral topology when neither earlier tier has enough
  evidence.

## Building The Orchard

The Orchard grew through source recovery, relation-family research, authored
fixtures, Replay integration, provider-free tests, and repeated visual review.
Its primitives are Babel's reusable visual language; Tier 1 composes them into
curated analyses, while Tier 2 lets the same pieces generalize without guessing
an unknown relation's name.

## Closing The Renderer

The relation renderer was verified and closed on August 25, 2026. The current
inventory contains 69 visual primitives across 70 output assignments and 52
executable Tier-2 recipes. Tier 1 and Tier 2 use the same production pixels.

That does not mean every possible syntactic relation is covered or that every
analysis is beyond criticism. It means the deterministic architecture now has
an honest answer for exact relations, structurally recoverable claims, and
unknowns.

## Continuing The Library

If a relation is missing, or if I or one of the models I worked with made a
mistake, please open an issue with a source, an example tree, and an explanation
of how the relation maps to Babel's current contract and visual language.
