## Why this matters

The replay derivation compiler — the code that turns server `derivationStages`
into ordered playback steps, materializes trace leaves, aligns workspace
forests, and places visual-relation steps — is ~8,300 lines of **pure,
React-free logic** living at the top of a React component file
(`components/TreeVisualizer.tsx` lines ~60–8364; the component
`const TreeVisualizer: React.FC` starts at line 8365; the only React usage
above that line is the import statement).

Consequences, all observed in this repo today:

- **It cannot be tested.** `scripts/verifyReplayRegression.mjs` (932 lines)
  cannot import the compiler, so it validates *captured render JSON* from
  machine-local Playwright runs instead — which is why `npm run verify:replay`
  fails on a fresh clone (plan 003 context).
- **It is the highest-churn, zero-test surface.** 38 commits touch this file
  in 2026; the current dirty tree modifies it again (indexed traces `t_1`,
  per-stage microstep suppression). Every change is verified by eyeball.
- **It blocks the visual-relations roadmap.** The design doc
  (`docs/design/babel-visual-relations-research.md`, "Babel Implementation
  Bridge") plans a relation compiler and Three.js overlay against this exact
  logic; building that inside a 10k-line component file is not tenable.

After this plan: the compiler lives in `replay/*.ts` (plain TypeScript, no
JSX), unit-tested against the plan-003 fixtures via committed snapshots, and
`TreeVisualizer.tsx` shrinks to the rendering component plus imports.
