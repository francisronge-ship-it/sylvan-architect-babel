## 0. Plain-English summary

The benchmark measures whether a frontier model can author complete staged syntactic derivations. The models tested in each release are **chosen by Francis** and frozen in a published, reproducible release manifest; the standing expectation is that the most important new frontier models — Chinese, Western, open-weight, and closed — are tested, at every native reasoning tier the release requires, but no tracker, hub, nomination, or automatic rule can enroll a model. Every selected model runs the full required suite; a model that cannot technically complete it produces reported outcomes, not an exclusion. What runs is what the release's claims require (claim classes C1–C4, §2); the native-tier coverage policy itself is decided by the E5b pilot and Francis — it is open, not settled. Cost, tokens, and latency are measured and reported — they never shape sample sizes, coverage, reruns, inclusion, or adjudication quality. Nothing is graded against one gold analysis; adequacy means the model's own derivation is internally defensible. Statistical machinery is never borrowed on faith: item-response-theory models are candidates that must pass a validation program on Babel's own data, with plain clustered proportions as the always-available fallback. Private items follow an honest exposure model. Every number ships with uncertainty and drills down to the underlying derivations.

**Babel's evaluation object, stated directly:** the benchmark evaluates whether a model can author a complete, internally coherent, defensible staged syntactic derivation of a given input under a declared framework and recorded conditions. Defensibility is judged against the derivation's own commitments and the item's conditional checklist; there is no mandatory gold tree and no gold analysis family (families are non-normative reviewer aids, §6); legitimate theoretical and analytical multiplicity is treated as legitimate.

## 2. Capability, claims, forbidden claims

**Measured:** explicit derivational syntactic competence — authoring complete, internally coherent, defensible staged derivations (CA §2) under recorded conditions, including memorization-resistant inputs. **Claim form:** "under contract vX, framework F, model M (resolved version V, host H) at native tier E, suite S, window W." **Forbidden:** "knows/understands syntax"; presenting register-listed prompt-stated constraints (CA §7) as discovered capability, or counting them in adequacy (they live only in discipline/coherence); "human-level"; best-framework claims; cross-provider tier-name equivalence; full-characterization claims omitting supported native tiers; adequacy claims before stage D3 (§8); headline claims from non-native partitions; provider-non-exposure claims after that provider's API has run the item (§9); population claims beyond §3.5's manifest-scoped form. A published **testing-and-claims policy** (ARC's pattern) is the instrument. Engine faults (CA §5.1 class 5) invalidate runs — fixed, re-run, errata'd; never scored; engine certification (CA §5.5) precedes all scored multilingual/novelty runs. **Configuration claims (claim classes; the tier matrix is open pending E5b):** C1 — competence characterization: minimally the documented default + documented maximum profiles; whether C1 releases may stop there is exactly what the E5b pilot decides [→ FRANCIS]; C2 — reasoning-scaling: all native settings of the covered models (always a full-sweep release for them); C3 — cross-model comparison: paired at named profile pairs (default↔default, maximum↔maximum), reported under per-provider labels in separate columns, never merged or name-equated; C4 — intermediate-setting anomaly detection: ≥3 settings per family (the pilot's own claim). Models without exposed controls are one recorded condition. Dynamic/adaptive modes are characterized as label + observed per-run reasoning-usage distribution (usage fields recorded on every run; percentiles published per condition). Within-model across-setting comparisons are valid ordered conditions; across-model same-label comparisons are invalid; external scaffolding is out of scope. **Unsupported commitments**, mechanically anchored: (a) a relation unlicensed by its stage record (deterministic check; live rule `systemInstruction.js:103` [VERIFIED-CURRENT]); (b) a prose claim contradicted by the authored states, citable by the reviewer as a specific state/record mismatch; "theory says otherwise" is inadmissible.

## 3. Model selection and release manifests (Francis selects; full-suite execution) [SETTLED]

**3.1 Selection authority.** Francis chooses the models included in each benchmark release. The standing expectation — a statement of intent, not a rule with enrollment force — is that the most important new frontier models are tested: Chinese, Western, open-weight, and closed alike. **No tracker, hub, leaderboard, nomination process, lab list, or automatic rule has authority to enroll a model**; there is no census, no constructed lab list, no per-window surface set, no disposition duty toward unselected models, and no `not-evaluable`/`deferred-cost` queue. A model Francis has not selected is simply outside the release's claims.

**3.2 The release manifest (reproducibility instrument).** Each release freezes and publishes a manifest of Francis's selections, recorded per model: exact model identity; resolved version (immutable snapshot where the provider offers one; else `alias-mutable` with the observed version string and the run window — never mislabeled as pinned); provider and host route(s); API and API version; the model's documented control set verified against its **own model page** (family-level documentation is never per-model evidence — the family "can include" sets differ from per-model sets, verified 2026-07-23), with page link, retrieval date, and admission-probe confirmation recorded; **every native reasoning tier tested** (the complete official tier list is recorded, and the manifest states which tiers the release requires — full-characterization releases run all of them; tier-subset cycles scope their claims explicitly); all request parameters as sent (temperature per [SETTLED-10]); and run date-windows. The manifest is frozen at launch authorization, before scored runs begin; mid-release additions are manifest amendments, published as such.

**3.3 Full-suite execution (no admission gates, no early exits).** Every selected model runs the release's required conditions and tiers in full. Foundational items remain ordinary items and reporting strata (§5 purpose flags) — they never gate admission, never truncate a model's run, and there is no `below-floor` status or early-exit path. A model that cannot technically complete the suite — persistent API failure, no valid derivations, refusals, transport breakdown — produces **reported measured outcomes** under the CA §5.1 typed failure taxonomy, published like any other result; technical inability is a finding about the model under the recorded conditions, never an exclusion mechanism.

**3.4 Registry entries.** Per selected model: canonical name; lab; resolved version/alias labeling as in §3.2; host route(s); API+version; complete native tier list from official docs (verified by an admission probe before scored runs); documented sampling defaults; limits; per-category prices; transport capabilities; retention/no-train tier availability; status (active / retired-archived). Version change → new condition; retirement → archived history with results retained.

**3.5 The honest claim.** "This release evaluates **the models Francis selected, as frozen in manifest M_R**, at the tiers listed there, under the recorded conditions." Completeness is manifest-relative; absolute frontier-ness is never claimed; no claim of any kind is made about unselected models. Geography and provider names appear nowhere in the rules. Francis supplies the release roster; the system verifies the official documentation and technical availability of the models he selected (per-model pages; admission probes) and generates or maintains no candidate roster of its own.

## 4. Units, conditions, provenance

**Item** (§5). **Condition** = (registry model @ resolved version or labeled alias-window; host; API version; framework; native tier; all request parameters as sent — temperature omitted [SETTLED-10], documented default recorded, `default-required` where an API forces a value; completion limit sent; carrier = the CX-carrier outcome, harness carrier-parameterized until then; prompt/contract hashes; engine version; system fingerprint/service tier where exposed; run date-window; `unpinnable-behavior` notes; per-condition observed reasoning-usage distributions computed and published per §2). **Run** = one call under one condition on one item: raw text (archived, hashed); typed outcome class + sub-cause (CA §5.1); finish reason; normalized bundle when valid; latency; tokens (input/output/reasoning/cached where exposed); labeled cost. The benchmark request builder is independent of product routes (the live 0.2 Gemini temperature vs. Google's default-1.0 guidance, [Gemini 3 guide](https://ai.google.dev/gemini-api/docs/gemini-3), accessed 07-22, is the standing reason). **Judgment** = one reviewer's structured evaluation of one valid run on the §6 dimensions, with rationale, rubric version, blinding record. **Release** = frozen tuple (suite version; contract hashes; engine version; release manifest + condition matrix; all runs/scores with uncertainty; adjudication records + reliability statistics; anchor deltas; correction ledger; claims document; downloadable data per §12).

## 5. Items

**Content axes:** input string; language; script; frameworks (results always reported per framework, never averaged — frameworks are not interchangeable); primary phenomenon tag (+secondaries); novelty class (none / nonce / template-lexicalized / conlang-specification / minimal-mutation); conditional checklist (entries may demand only stand-taking, conditional obligations of the model's own chosen analysis, or register-stated compliance items); family documentation (reviewer aid, non-normative); ambiguity spec (any single adequate analysis earns full adequacy by default — the live contract does not force enumeration, `systemInstruction.js:50–51` [VERIFIED-CURRENT]; a dedicated enumeration sub-suite scores family recall; structural duplicates are coherence violations). **Purpose flags (authored, non-exclusive, operational):** `foundational` — baseline contract-and-phenomenon competence any qualifying model should demonstrate (roles: scale anchoring; reporting stratum; regression alarms — any later failure is a flagged event; never an admission gate); `control(target, factor)` — differs from its target in exactly one factor, for attribution; `calibration(baseline)` — carries a human-expert baseline authored under the same contract semantics (GPQA logic); `adversarial` — an input whose tempting analysis is subtly incoherent, measuring whether the model authors the incoherent shortcut; never a scoring key. Authored purpose flags are orthogonal to **observed difficulty bands** — "discriminating"/"frontier" are population-indexed regions of the observed scale, computed per release, never authored labels. **Observed difficulty (computed, never authored):** early releases publish per-item population pass-rates with CIs; model-based difficulty (IRT) only after §7.4's validation program adopts a model; classification labels are regions of whatever scale is in force, published as reporting policy with their derivation. Universal passes/failures stay informative (alarm/headroom); never removed for uniformity. **Lifecycle (HLE-Verified pattern):** draft → reviewed (D2+ dual; D0 Francis-only, labeled) → piloted → active(vN) → per-cycle audit under the error taxonomy (key error; underspecified checklist; family-doc gap; ambiguity defect; contamination evidence) with three-way disposition **verified / revised(vN+1, dual-version score republication) / documented-uncertain** (published; excluded from claim-bearing scores until resolved) → retired-for-cause (published reason). Rolling reviewed intake (HLE-Rolling pattern) is the formal additive-growth mechanism. All computed statuses are (release, population)-indexed with history.

## 6. Judged unit and adjudication

**Judged unit:** every valid run in the adjudicated item-set — no representative selection of any kind (no best/worst/median/modal/random); cherry-picking is impossible by construction; workload is controlled by which items enter the adjudicated set (S2-designed), never by run selection; drill-down shows all runs. **Dimensions:** (i) internal defensibility (checklist satisfaction; absence of cited derivation-internal defects); (i′) **phenomenon coverage** — does the derivation engage the structures the input contains, judged against the conditional checklist and the input, never a gold tree (the anti-vacuity dimension: a coherent-but-evasive derivation scores low here); (ii) argumentation quality (3-point anchored ordinal); (iii) faithfulness flags (§2's unsupported-commitment anchors); (iv) family-choice recording (descriptive only — **the score never references family identity**; families are reading aids; novelty is adjudicated by internal defensibility with the rejection burden below). **Rejection burden:** a rejection must cite a specific line-referenced defect; "not in the literature"/"unfamiliar" is procedurally inadmissible (no such field exists on the form; adjudicators enforce). **Protocol:** two independent reviewers per judged run in the double-rated share; single-rating for the remainder, with the **ongoing double-rating share d an S2 design output** (chosen by the §7 simulation to hold agreement-coefficient CIs and drift detection at claim-grade precision — never a fixed percentage; the initial calibration set is fully double-rated, a mechanical purpose-stated exception); adjudicator on splits; rationales are artifacts; no self-review; reviewers blind to model identity; run order randomized; balanced-incomplete reviewer pairing; item authors blind to reviewer assignment. **Symmetric neutrality audit:** each release, an independent expert blind-re-reviews random samples of rejections **and** of family-matching acceptances; disagreement rates published; systematic findings force rubric revision + errata. Evaluation in this benchmark consists of human review, deterministic contract validation, and statistical analysis. **Authorship and roles:** Francis may author items (designer-author) — credibility is preserved by process, not exclusion: independent dual expert review of every claim-bearing item regardless of author; author identity in the per-item audit trail; **no self-adjudication** (no one adjudicates disputes on items they authored); mixed-author calibration sets so authorship-style effects are detectable; the neutrality audit samples across authors. Annotators perform deterministic pre-checks only (schema conformance; checklist completeness) — no linguistic judgment; the [METHOD-EXPERT] verifies the §7 design, simulation code, and alpha-spending; every judgment's provenance and rationale is a release artifact.

## 7. Statistical design (estimand-derived; sequential; constants are labeled conventions, never discovered; measurement models validation-gated)

**7.1 S0 — design policy, declared before data [FRANCIS]:** the pre-registered claim list mapped to estimands (per-condition profile rates on each dimension×stratum; paired named-profile contrasts on shared items; within-condition stability; reliability; strata descriptives; longitudinal anchor deltas; rare-event failure rates); the reporting granularity g — the smallest displayed difference (recommended initial g = 5 percentage points, a labeled convention derived from achievable pilot widths, [METHOD-EXPERT]-reviewable, never a discovered constant); per-claim power/precision targets (recommended 0.8 power at two-sided α = 0.05 — labeled standard-practice convention); reliability floors (a dimension enters claim-bearing scoring only when its agreement coefficient's lower 95% bound meets the declared floor; recommended 0.6 on the weighted-κ scale, labeled convention); judge-severity drift bounds; and the mandatory three-valued outcome rule — every decision point resolves adopt / reject / **hold**, and holds are published as holds.
**7.2 S1 — prior-free pilot with optimal-allocation expansion:** the cited variance literature ([arXiv 2411.00640](https://arxiv.org/abs/2411.00640); [arXiv 2406.10229](https://arxiv.org/pdf/2406.10229)) establishes the component *structure* — item and rerun variance are both real and large on reasoning-model evals — but contains **no numerical priors for Babel's components**, so none are invented. Stage-1 block: every manifest model × its full native settings (hosting **E5b**, the tier-informativeness pilot, built around the actual decision — *would omitting an intermediate setting remove materially distinct behavior relevant to the intended release claims?* Per intermediate setting: pre-registered comparisons against **both** neighboring settings over complete outcome distributions (adequacy dimensions; typed failure-class **composition**, not just rates), stability (rerun consistency), item/phenomenon-stratum interactions, and reasoning-usage distributions; multiplicity controlled within pre-declared families (Holm); precision pre-declared per comparison. Outcomes per setting: **distinct** — materially distinct behavior at declared precision → releases characterizing that model include the setting or explicitly scope claims to exclude it; **redundant-for-claims** — every pre-declared comparison shows no material difference; **hold/indeterminate** — underpowered → the setting **remains included** and the pilot extends immediately under the S-design expansion (an underpowered first decision is repaired now, never deferred to future releases). Linear interpolation between neighbors is never an inference basis. **Francis converts the evidence into the tier policy; no cadence is settled here**) × 24 stratified items × k = 3 reruns, fully double-rated. Honest width statement: a per-condition rate over n = 72 runs has worst-case (p = 0.5, independence) 95% half-width ≈ 11.5 pp — wide, stated, non-claim-bearing; the block's purpose is component estimation and calibration. **Expansion (correcting the defective width comparison):** after each block, refit the crossed variance-components model (item; item×condition; rerun; rater; item-author) and allocate the next block by **marginal variance reduction per added run** — d(SE²)/d(items) versus d(SE²)/d(reruns), the optimal-allocation criterion; k never rises merely because more reruns shrink an SE (everything shrinks an SE); k rises only when rerun variance binds a declared estimand, and E-stability claims independently require k ≥ 2 on their designed subset.
**7.3 S2 — design by simulation; stopping:** choose N per claim, k per item class, the adjudicated-subset size, and the double-rating share d by simulating the crossed design over component posteriors, requiring every S0 target across the middle 90% of draws; S1 stops when (i) two successive re-simulations select the same design, (ii) that design meets every target across those draws, (iii) conclusions survive prior-sensitivity refits (diffuse and half-width priors), and (iv) each design-driving component's posterior width has stabilized below its S0 bound. Publish code, draws, and the design.
**7.4 Measurement-model selection and validation (borrowed machinery is never assumed to fit):** candidates — clustered raw proportions (**the default and permanent fallback**); continuous-response 2PL; graded-response; Rasch/partial-credit; hierarchical Bayesian item models. Program: assumption checks on Babel's own data (dimensionality per dimension; local independence — Q3-type residual dependence; rater dependence via facet extensions or pre-aggregation with propagated uncertainty; **differential item functioning across frameworks and languages** — expected, and either modeled or stratified); fit comparison (information criteria; posterior-predictive checks); linking validity (anchor-parameter stability across windows); adoption rule: a model is adopted only if assumptions pass, fit beats raw proportions on predictive checks, and its estimates are stable under leave-strata-out perturbation; otherwise clustered proportions remain the reporting basis. Design and sign-off of this program: **[METHOD-EXPERT]** (benchmark/statistical methodology consultation) with Francis governance approval; syntacticians own item validity, not measurement modeling. Generic infrastructure (response matrices; fitting/diagnostic tooling) is safe to build; *adoption* of any IRT model is gated on this program's result.
**7.5 Estimators and handling:** cluster-robust CIs (item clusters; wild-cluster bootstrap when clusters are few); paired contrasts on shared items; Beta-Binomial intervals for rare events with explicit indeterminacy statements; ordinal mixed models or pre-registered dichotomization; multinomial per-class CIs; rater-effect propagation into score uncertainty (no bare agreement-threshold gates; per-type coefficients — Gwet's AC1 for nominal/skewed binary, quadratic-weighted κ / ordinal Krippendorff's α for ordinal — reported with bootstrap CIs; dimensions failing claim-grade precision are descriptive-only); judge-severity modeled as random effects in an ordinal mixed model, with per-window drift checks on re-rated control runs (a severity shift beyond the S0 bound → recalibration before further claim-bearing judging); judge-missing judgments → optimistic/pessimistic sensitivity bounds reported; missingness (invalid runs are outcomes; engine faults re-run; judged-missing excluded with sensitivity analysis); multiplicity (pre-registered primary family + Holm; else exploratory-labeled); no pooling across resolved model versions; **S3** group-sequential alpha-spending for monitored comparisons; deviations documented.

## 9. Private data (honest party model)

**Parties and "private" against each:** (a) training corpora — private = never published (the primary protection); (b) **model providers whose APIs receive prompts** — any API evaluation is an **exposure event**, ledgered (provider, date, retention tier); retention/no-train commitments (recorded per registry entry from official terms) reduce training risk but never undo exposure; no non-exposure claim survives an API run; (c) **local/open-weight execution** on operator-controlled hardware exposes nothing to any provider — private items can remain provider-unexposed for the open-weight subpopulation, and the ledger distinguishes these runs; (d) submitters/participants never receive private items; provider-run submissions cover public items only; private grading of a provider's model = operator-run inference (a ledgered exposure to that provider); (e) contributors see only their items; funders/operators: any provider funding or access is publicly disclosed (FrontierMath lesson); custody = encrypted store under Francis, key access logged, every decryption audited; leak response = retire-for-cause, replace, publish the incident. **Lifecycle:** no scheduled rotation; no call-count "budget" (withdrawn as unevidenced); rotation triggers are leak evidence, a positive memorization-probe signal (verbatim-continuation tests per item), or saturation-driven redesign; whether a quantitative exposure-risk budget is even constructible is an [EMPIRICAL gate] (pilot memorization dose-response study). **Anchors** are the deliberate exposure spend, monitored by the twin-gap method (matched unexposed twins run periodically; a widening gap is labeled evidence, never proof). Canaries cover published files only (stated). Unspent-probe pool maintained; probes are spent on first use and reclassified `exposed(provider, date)`.

## 10. Governance, corrections, versioning

Immutable releases; correction ledger with dual-version republication of affected scores; per-cycle **human audits** of items/keys/checklists/adjudications under the §5 error taxonomy; evidence-triggered per-item retirement; additive growth (rolling intake); cross-version claims only on item versions shared identically between releases; the published testing-and-claims policy; standing disclosure of provider funding/access.

## 12. Reporting and cost
