## 4. Problem resolutions

### P1 — Cross-stage identity and transition witnesses

**The mechanical inspection (run this pass on the register file):** all 156 register rows scanned; **17 rows involve cross-stage transitions** (R01.03, R01.08, R03.01, R04.07, R06.07, R08.01, R08.03–.10, R08.14, R12.14, R13.07); transition-relevant fixtures F18, F21, F34–F37, F39, F40, F57, F61. The 17 split decisively:

- **State changes on persisting objects (12 families):** valuation (R03.01), vocabulary insertion (R08.01), impoverishment's feature-deletion variant (R08.05), readjustment (R08.08), local dislocation (R08.10), conflation (R04.07/R08.14), zero realization (R12.14), lowering/sideward copies (R01.03/R01.08), merger-as-structure (R08.09), derived replay states (R13.07 — Layer E, never authored). **Persistent node `id`s already resolve these deterministically**: the same object carries the same id across stages (live rule, line 89); before/after content is `values` literals on a relation anchored to the persisting node. No new mechanism.
- **Identity/existence transitions (the genuinely unresolved ~5):** fusion (R08.03 — two objects cease, one new object exists), fission (R08.04 — one ceases, several new), node-deleting impoverishment/obliteration (R08.05 variant, R06.07/R08.07 — an object ceases), pruning/whole-node deletion, and any replacement/reanalysis where the model does not persist the id. Here the relation's participants **never co-exist in one stage**, so same-stage anchoring cannot witness both sides, and naming the other side in a value is (a) not machine-resolvable and (b) flagged by the `value_matches_node_id` rule — a genuine contract gap the previous dossier papered over.

**Alternatives compared:** (A) unrestricted cross-stage anchors — destroys the one-stage audit property; (B) lineage-merging (multi-lineage arrays) — complicates every consumer and forces a "primary continuer" theory choice; (C) two coordinated relations at k−1 and k — models may omit one, and linking them back requires exactly the name/witness heuristics Babel forbids; (D) relation IDs + cross-references — a whole new reference space for one use; (E) **a single optional `priorAnchors` block resolved against the immediately preceding stage** — chosen.

**The mechanism (exact, minimal, theory-neutral):** a relation item may carry, beside `anchors`, an optional **`priorAnchors`** object (open role names → node id or id array) whose every value must resolve in the **immediately preceding stage's** expanded workspaceForest. Validation is deterministic (check stage k−1 exactly as `anchors` checks stage k). Semantics: the relation is a commitment about the transition into this stage. Rules: meaningful only at stage index ≥ 1 (typed error at stage 0); a relation must have at least one non-empty anchor block; the live line-99 prohibition ("do not anchor to an id that appears only in an earlier stage") gains exactly one exception — the `priorAnchors` block; the invention detector's universe for such a relation is the union of the two adjacent stages' authored ids. No renderer microsteps are forced: replay draws prior→current correspondences at the stage boundary it already animates; static views list the transition in the stage timeline/inspector; the fallback badges the prior-side witnesses in the previous stage's view with a "from previous stage" panel note. No analysis family is privileged: any framework's transitions may use it; none must. Contract path: a CE-2 model-visible factor (**F-T**) with its own evidence arm.

**Relation identities / relation-to-relation references — bounded exclusion (not a resolution).** The four demanded test cases: *failure of a specific operation* — self-contained: the failure relation itself anchors the participants and states the outcome (R13.02-family); no reference needed. *Repair/override of a particular commitment* — self-contained: the overriding relation anchors the same persisting witnesses and states the superseded value as a literal; deterministic when the prior instance is unique for (stage, name, witnesses). *Ordering between relations* — stage placement orders across stages; same-stage grouping/ordering is a covering relation over shared witnesses. *Repeated same-name/same-witness instances* — distinct values ⇒ distinct instances; identical ⇒ flagged duplicates. **The residual case — structurally citing exactly one of several same-stage, same-name, same-witness instances that differ only in values — has no deterministic structured encoding in the current contract; there is no field that cites a natural key. It is excluded as unsupported by any attested register row — excluded, not resolved.** The minimal future mechanism is specified but not adopted (PROOF §2): an optional **derivation-unique** relation `id` (duplicate → typed error) plus an optional `targets` block (role → relation id; resolved against any earlier-or-same stage; unresolvable → typed error), with persistence (ids stored/exported verbatim), rendering (targeting marks attach to the target's marks), and migration (absence valid) defined; adoption would be its own CE factor.

### P2 — The open relation-local field

**Name.** Candidates compared on syntactic naturalness / neutrality / steering risk / coverage-signal: `values` (natural for key→literal maps; symmetric with `anchors` — anchors point into the tree, values hold literals; mild valuation echo; **signals short-literal content shape**, which is the built-in prose deterrent); `info` (neutral but invites prose dumps — the field reads as a notes slot); `content` / `details` (prose-suggestive); `data` / `properties` / `attributes` / `metadata` (programming/metadata register; `metadata` actively wrong — this is authored commitment content, not metadata); `features` (theory-laden — rejected outright); `notation` (too narrow — excludes statuses/orders). **Recommendation: `values`** — reversing my previous `info` recommendation for the stated independent reason (content-shape signaling beats blandness; the dump-resistance requirement outweighs the small valuation echo, which the field description neutralizes). The name remains formally open; if Francis wants belt-and-braces, a one-token A/B (`values` vs `info`) rides the CE-2 arm at zero marginal cost — steering metric: distribution of authored key content classes (valuation-like vs status/form/order/other) and prose-length distribution; decision: the name with broader non-valuation coverage and shorter literals; tie → Francis.

**What belongs / what does not.** Belongs: any authored relation-local commitment that is not an anchor — outcomes, statuses, assigned forms/categories, orders, branch claims, identity types, verbatim notation strings. Does not belong: prose argumentation (that is `stageRecord`'s job — stated in the contract line); node references (flag `value_matches_node_id` retained — and no longer needed for transitions, which use `priorAnchors`); renderer instructions (never); provenance/database metadata (lives outside the authored payload).

**Shape and types (exact).** Flat map: `values: Record<string, string | string[]>`. Keys: open, non-empty, unique post-parse (byte-level duplicate keys are invisible after JSON.parse — recorded as a known transport limitation, low risk, not silently "handled"). Accepted value types: **string, or array of strings — nothing else**. A number, boolean, null, or object value is a **typed class-3 validation error naming the key and the received type**. Rationale: JSON parsing does not preserve number spelling (`1.10` parses to 1.1), so numeric literals must arrive as quoted strings to keep their exact decoded form; Babel never silently rewrites authored content, and the error is trivially fixable by frontier models. This replaces (and corrects) the previous revision's silent-stringification proposal. Empty string: legal (an authored empty literal, displayed as such). Empty array: **typed error** — an empty collection asserts nothing and invites omission-as-assertion confusion; authored "none" claims are literal strings or status keys. Duplicate array entries: preserved and displayed (order/positions distinguish them). Order: array order survives parsing exactly and is displayed as authored; the contract does not declare order meaningful — a relation's own semantics (or a registry signature) may. **Fidelity layers (used by every "verbatim" claim):** archived raw response bytes are byte-preserved and sha256-hashed; parsed values preserve exact decoded string content (code points) and array order — not source escapes, number spelling, duplicate object keys, or wrapper bytes; canonical reserialization is a derived form, never the original stream. "Verbatim" means decoded-content-exact.

**Multiplicity — the rigorous definition.** A relation item is the tuple **⟨name n, anchors A, priorAnchors P (optional), values V⟩** and asserts exactly **one instance** of the relation n holding of the assignment (A ∪ P) with recorded content V. Interpretive rules: (i) **joint** — all members of an array-valued role participate together in this single instance (the instance is natively a hyperedge); (ii) **parallel/distributive/repeated** — n distinct instances are authored as n items; nothing in one item enumerates instances; (iii) **grouped** — if the model asserts that several instances form a unit, that assertion is itself a commitment, authored as a covering relation over the shared participants (grouping is content, not convention); (iv) **cross-stage** — via `priorAnchors` (P1); (v) **exact duplicates** (same stage, name, assignment, values) — flagged `duplicate_relation`, displayed once with a multiplicity marker, never silently dropped; (vi) role association holds only within an item — across items, none is implied; the renderer may *visually cluster* same-name same-stage items for legibility, which is presentation, asserts nothing, and is labeled as clustering. This definition covers every case in the former C-GROUP adversarial table: bijections, one-to-many, many-to-one distributive (n items), joint many-to-one (one item, array role), many-to-many (n items), optional members (omitted keys), duplicates (positions/instances), with **zero authored conventions beyond order preservation**.

**Prose-dump discouragement (not "harmless").** Three mechanisms, honestly scoped: (1) the name and description — "each key names one relation-local aspect; each value is the authored literal for it; argumentation and narrative belong in stageRecord" (no linguistic examples; no length numbers — thresholds stay deleted); (2) the existing structured-vs-prose boundary line extended to the field; (3) the benchmark's discipline dimension may cite misplaced prose as a specific defect. Mechanical length policing is deliberately absent (it would recreate the deleted-threshold defect); this is a stated-discipline rule with review-time teeth, and the packet says so plainly.

### P3 — Generic rendering for unregistered relations

**What the inspected practice does** (corpus: the repo's 24 cached plates [PAGE-VERIFIED in-repo], the graduate-text conventions in the notation survey [statuses per PROOF §5], and standard tree tools — qtree/forest/TikZ idioms; **an inspected corpus, not a field census**): when a relation has a dedicated convention, this corpus draws it (movement arrows, probe–goal arcs, region boxes, strikethrough). When it does not, **the corpus does not invent a connector network — it co-indexes the participants on the tree (subscript indices) and states the relation off-tree** ("where DP₁ … binds pro₂ …", numbered example lines, legends). Co-indexation plus a stated relation is the generic mechanism throughout this corpus. No generic hub-and-spoke connector convention appears in it — a corpus observation; field-wide absence is not claimed (hub-and-spoke forms come from knowledge-graph visual culture). Arcs are attested but **not neutral in this culture** — an arc between tree nodes strongly connotes movement/dependency, so defaulting arcs onto arbitrary relations (identity, mere association) would over-assert.

**Fallback families compared:** (α) labeled undirected arcs/connectors — practice-attested for dependencies but over-connoting as a generic default; legibility degrades badly with overlapping relations in dense trees; (β) **index-badges + relation panel** — each unregistered relation instance gets a numbered badge (①, ②…) on every witness node plus a panel/legend entry "① ⟨authored name⟩ — role: node…, key: value…" with bidirectional selection-highlighting; (γ) labeled hub-and-spoke (my previous recommendation) — universal arity but culturally alien and clutter-prone; (δ) braces/grouping marks — attested for collective constituency emphasis; right as *registry* geometry for collective roles, not as the generic default; (ε) inspector-only — fails the visibility duty.

**Recommendation: (β), the "citation form."** It matches what a syntactician would do (index the participants; state the relation); it renders every authored fact renderably: anchors (badged witnesses), roles (panel + hover labels on witnesses), order (ordinal positions within the panel entry and superscript position marks on badges — numbers, never arrowheads), values (verbatim panel rows), `priorAnchors` (badge in the previous stage's view + "from previous stage" note); it is arity-uniform (unary = one badge; binary and n-ary identical mechanics); it stays legible in dense trees (small badges, no edge clutter; >3 badges per node collapse to "+n", expandable); it works in static Canopy (badges + panel below the tree — paper-like), Growth/Replay (badge appears at its authored stage; panel is stage-scoped), workbench lenses (per-relation-name toggle groups), accessibility modes (badges are shape+number, not color-only; the panel is plain text; reduced motion honored), and export (badges and panel print). Deterministic geometry: badge order per node = (stage index, authoring order); panel order = same; selection priority = most recently selected instance, then stage order; collision handling = stacking then collapse, never silent drop. Degradation: an unresolvable anchor is an upstream typed contract error (invalid authored data — never rendered as if valid); renderer overflow is a declared visual state ("+n"); the two are never conflated. The reserved badge style is defined once in the legend as "authored relation without a curated visual convention" — a generic drawing **never impersonates a specialized convention**. Optional user-toggled neutral arcs for binary instances (off by default) serve users who want them, without making the over-connoting form the default.

**Candidates delivered to Francis (R10):** β (recommended); β+α (badges with opt-in arcs); γ (labeled hub-and-spoke). Each is fully specifiable; the architecture (licensing, layers, degradation, provenance) is identical across them, so the choice is pure visual craft — which is exactly where Francis's authority sits.

**The specialized registry is preserved** (and was re-derived, not merely inherited, in the prior revision): a recognized authored relation whose anchors/values satisfy a Francis-approved entry's required signature triggers the approved specialized visualization — authored Movement with its required anchors produces movement arrows; authored Sharing/Multidominance produces the existing shared-node visualization (the lab's working lens, `visual-relations-lab-adapter.ts:215–221`); the display object may thus show multiple mothers even though the stored structure is a tree plus a relation. Registry generalization spans the full inventory via the register's grammar targets (G1–G33), each reachable exactly when its entry passes the five gates and the authored signature is complete; absent that, the fallback above — never a guessed specialized drawing.

- **C1 — "characterize M's derivational competence":** minimally supportable by M's *documented default* (the provider-endorsed condition users actually get) plus *documented maximum* (the capability ceiling). Whether C1 releases may stop there is exactly what the pilot below decides.
- **C2 — "how does competence scale with reasoning on M":** requires all native settings of M (a dose–response claim); always a full-sweep release for the models it covers.
- **C3 — "compare M and N":** paired contrasts at **named profile pairs** (default-vs-default; maximum-vs-maximum), reported under per-provider labels in separate columns — never merged, never cross-label equated. Provider-specific controls are reported verbatim with their documentation link; no cross-provider tier synonymy exists anywhere in the schema.
- **C4 — "are intermediate settings behaviorally anomalous":** requires ≥3 settings per model family at least once — the pilot's own claim.
- **No exposed controls:** one condition, recorded as such; the model simply has a one-point profile.
- **Dynamic/adaptive modes:** the condition is the label **plus the observed per-run reasoning-usage distribution** (all three providers expose usage fields); reports show usage percentiles per condition, which is the honest continuous description beneath the discrete label.

**The deciding pilot (tier-informativeness; rebuilt around the actual decision):** the question per intermediate setting is *would omitting it remove materially distinct behavior relevant to the intended release claims?* — native labels are ordered provider controls, not points on a linear scale, so redundancy is never inferred from interpolation. Within the S1 pilot, every manifest model with ≥3 native settings runs its full native set. Per intermediate setting, pre-registered comparisons against **both** neighbors over: complete outcome distributions (adequacy dimensions; typed failure-class **composition**, not just rates); stability (rerun consistency); item/phenomenon-stratum interactions (pre-declared stratum families); and reasoning-usage distributions. Multiplicity is controlled within pre-declared families (Holm); precision is pre-declared per comparison. Outcomes per setting: **distinct** — any materially distinct behavior at declared precision → releases characterizing that model include the setting, or explicitly scope claims to exclude it; **redundant-for-claims** — every pre-declared comparison shows no material difference; **hold/indeterminate** — underpowered → the setting **remains included** and the pilot extends immediately under the S-design expansion (an underpowered first decision is repaired now, not by waiting for future releases). Either outcome leaves the methodology valid: conditions are manifest-listed, claims are scoped to conditions run, and the schema never encodes a tier policy. Francis takes the policy decision on this evidence.

### P5 — Benchmark statistics (rebuilt from estimands)

**Estimand table (what every published number estimates):**

| Symbol | Estimand | Estimator | Uncertainty |
| --- | --- | --- | --- |
| E-rate(c, d, s) | probability a valid run under condition c is judged adequate on dimension d in stratum s | clustered proportion (items = clusters) | cluster-robust (wild-cluster bootstrap when clusters < ~40) |
| E-contrast(c₁, c₂, d) | mean within-item difference on shared items at a named profile pair | paired difference | paired cluster bootstrap; Holm within the pre-registered family |
| E-stability(c) | probability an item yields the same adequacy class across reruns under c | within-item rerun agreement | bootstrap over items; **requires k ≥ 2 by identifiability** |
| E-reliability(d) | inter-judge agreement on d | AC1 (binary/skewed), quadratic-weighted κ and ordinal Krippendorff's α (ordinal) | bootstrap over double-rated runs |
| E-severity(j) | judge j's severity/leniency | random effect in an ordinal mixed model (runs × judges) | posterior/profile interval |
| E-difficulty(i) | per-item pass rate, population-indexed | raw rate with CI | Wilson/Beta-Binomial |
| E-failure(c, f) | typed failure-class rate | rate | Beta-Binomial (rare events; indeterminacy stated when intervals span the granularity) |

**Hierarchical dependence:** runs nested in item×condition cells; items crossed with models; conditions nested in models; judgments crossed runs×judges; phenomena as item strata; providers as model groups. Reporting basis: clustered proportions and paired contrasts (assumption-light); a Bayesian crossed random-effects model is the *engine* for variance components and design simulation, with prior-sensitivity checks — never itself a published score unless separately validated.

**Initial pilot — prior-free and defensible:** the cited literature (arXiv 2411.00640; 2406.10229) motivates the component *structure* (rerun and item variance are both real and large on reasoning evals) but supplies no Babel magnitudes; so the starting design uses worst-case binomial bounds that need no priors. Stage-1 block: every manifest model × its full native settings (jointly serving P4's pilot) × I₀ = 24 stratified items × k = 3 reruns, fully double-rated. Why these numbers: a per-condition rate over n = 72 runs has worst-case (p = 0.5, independence) 95% half-width ≈ 11.5 pp — wide, and stated as such; clustering makes it wider; the block's purpose is component estimation and calibration, not claims. **Expansion rule (correcting the defective width comparison):** after each block, refit components and allocate the next block to the unit with the larger marginal variance reduction per added run — d(SE²)/d(items) ∝ (σ²_item-mix + σ²_rerun/k)/I² versus d(SE²)/d(reruns) ∝ σ²_rerun/(I·k²) — the standard optimal-allocation criterion; k never increases merely because more reruns shrink an SE (everything shrinks an SE); k increases only when rerun variance is the binding component for a declared estimand, and E-stability claims independently require k ≥ 2 on their subset. Stop when every S0-declared target width/power is met across the middle 90% of component posteriors, the design choice is stable across two successive re-simulations, and conclusions survive prior-sensitivity refits.

**Numerical decision rules (auditable; parameters declared at S0, recommended defaults labeled as conventions):**
- Factor screening (CA §6 Phase 0): one-sided exact binomial test of candidate-loss count against the concurrent A0 self-pair loss rate at α = 0.05; can only reject or hold.
- Factor adoption: (i) zero losses adjudicated real (per-loss adjudication with its three admissible outcomes, unchanged — the qualitative core is sound; what was missing were numbers around it); (ii) the one-sided upper 95% confidence bound on each objective-harm difference (failure-class and coherence-violation rates, candidate minus incumbent) must lie **below the S0 granularity g**; recommended initial g = 5 pp, derived from achievable pilot widths, explicitly a convention subject to [METHOD-EXPERT] review — not a discovered constant; (iii) any bound straddling g → **hold/insufficient evidence** (the three-valued outcome is mandatory everywhere: adopt / reject / hold).
- Reliability gating: dimension d enters claim-bearing scoring only when its agreement coefficient's lower 95% bound ≥ the S0 threshold (recommended 0.6 weighted-κ-scale as the conventional "substantial" floor, labeled as convention); otherwise descriptive.
- Judge drift: control runs re-rated each window; a judge's severity effect shifting beyond the S0 bound → recalibration before further claim-bearing judging.
- Missingness: invalid runs are outcomes (never imputed); judge-missing judgments → estimates recomputed under optimistic/pessimistic bounds (reported as sensitivity range).
- Multiplicity: one pre-registered primary family per release + Holm; all else exploratory-labeled. Longitudinal monitoring under S3 alpha-spending.
- Model versions: never pooled across resolved versions; alias-window runs labeled.

**Cost separation:** cost and latency are recorded per run and reported (measured Pareto views); no formula anywhere maps cost into sizes, coverage, reruns, judging depth, or inclusion. An underfunded evidence-complete design delays or splits into transparently claim-scoped phases.

**Public experience:** tables and graphs mirror the frontier standard the operational study documents — per-condition profile tables with intervals; paired-comparison explorers; per-capability (stratum) drilldowns to runs, judgments, rationales, and raw bytes; correction history as a first-class view; uncertainty drawn in every figure; static site regenerated from released tables. Aesthetic craft passes a design gate; the methodological substance above is what the polish sits on.

### P6 — Benchmark content and human review

**Layer audit (each layer must earn its place by purpose):** the previous five-way item typology conflated authored properties with observed ones. Corrected two-dimensional design: **authored purpose flags** — `foundational` (baseline contract-and-phenomenon competence; anchors the scale; any later failure is a flagged regression event; never a gate), `control(target, factor)` (minimal pairs for attribution), `calibration(baseline)` (expert-authored human baseline under the same contract; GPQA logic), `adversarial` (inputs whose tempting analysis is subtly incoherent — measures whether models author the incoherent shortcut) — versus **observed difficulty bands** ("discriminating," "frontier" are population-indexed regions of the observed scale, computed per release, never authored labels). Every layer now has one purpose and no layer exists "because it appeared in a diagram."

**What an item is (exact):** a versioned tuple ⟨input text, language+script, framework directive, elicitation form (prompt-template version), conditional checklist (obligations conditional on the model's own analytic choices), family documentation (non-normative reviewer aid), purpose flags, a-priori complexity codes, provenance (author, reviewers, versions, dispositions)⟩. Families group items sharing phenomenon and documentation; phenomena tag from the register's 13 sections **as a floor, not a fence** — authoring may introduce phenomena beyond the current taxonomy, which then extend the register by the standard evidence procedure.

**Difficulty without circularity:** the triangulation stands — a-priori complexity codes (authored, model-independent), expert judgment (calibrated at D2), observed pass rates (computed, population-indexed, never redefining the first two). Published difficulty is the triple.

**Contamination — proportionate controls:** novelty ladder (attested → rare → nonce-lexical → template-lexicalized → constructed-language specification → minimal-mutation), private subset with exposure ledger, twin-gap monitoring, memorization probes; additive growth rather than rotation; refresh/retire strictly evidence-triggered (leak, probe signal, saturation). Public/private split: public items enable reproduction and community scrutiny; private items answer the contamination question; probes are spent on first use and reclassified. Proportionality argument: Babel's open-ended judged outputs are less answer-leakable than key-based benchmarks (no answer key to memorize), so the heavy protections concentrate where they pay — input-side memorization of analyses — which is exactly what the novelty ladder measures.

**Roles (Francis authorship resolved):** Francis **may author items** — he is the system's designer and an expert-adjacent author; credibility is preserved by process, not exclusion: every claim-bearing item passes independent dual expert review regardless of author; author identity is recorded in the audit trail; **no self-adjudication** (Francis never adjudicates disputes on items he authored; likewise any expert); the calibration set mixes authors so authorship-style effects are detectable; the symmetric neutrality audit samples across authors.
