## 2. The restored purpose [SETTLED]

Babel's visual-relations architecture exists so that **authored linguistic commitments receive their real, specialized drawings**: Movement authored with the required anchors gets movement arrows; Agree gets its probe–goal geometry and valuation plaques; sharing/multidominance gets the multi-parent overlay; domains get regions; correspondences get maps; fusion/fission get their joint and paired figures; intervention gets its gate; recognized failure relations get their violation marks; PF realization gets its plates; chains get their paths. The semantic boundary is **not** "names affect styling only." It is: **a recognized relation, together with the explicit anchors/values its approved grammar requires, licenses that grammar's semantic geometry** — the drawing is a rendering of an authored structured commitment, never an invented one. What remains absolutely forbidden is *inference*: Babel never derives linguistic content from `statement` or `stageRecord` prose, node labels, ID stems, vague name similarity, or missing fields.

## 3. The semantic visual-grammar registry (the dispatch/licensing architecture)

Four layers, strictly separated:

1. **The open authored contract** (CA §3): relation name (open string), `anchors` (open roles → same-stage witnesses), optional relation information (the `values` candidate per PROOF §2: strict string types, multiplicity semantics, optional `priorAnchors` transition block). Nothing here is registry-aware; models never author drawing instructions.
2. **The Semantic Visual-Grammar Registry (SVGR)** — versioned, Francis-gated, born empty. One entry per approved grammar:
   - **Relation identity matcher:** the exact recognized relation strings and explicitly approved variants (including approved non-English variants), with the only permitted normalization being declared case/whitespace folding. No regex fuzz, no similarity, no substring matching — an unlisted name never matches, partially or otherwise.
   - **Required signature:** the anchor roles (names, arities, structural requirements; transition signatures may require `priorAnchors` roles, resolved in the immediately preceding stage — e.g., Movement: `source` and `landing` witnesses, or one ordered chain array; Sharing: `parents` (≥2) + `shared`; Agree: `probe` + `goal`(s), valuation keys when the plaque variant is licensed; correspondence: per-correspondence relation items; fusion: joint array inputs + output (`priorAnchors` for the ceased inputs); fission: one joint split item (outputs array + `priorAnchors` input) with per-output content as separate items; intervention: `probe`/`goal`/`intervener`; recognized violation relations: their attempted-dependency witnesses and status role) and any required/optional `values` keys with their conventions. Signatures reference **only authored structured fields** — never prose, labels, or IDs.
   - **The specialized grammar:** the approved geometry (arrowed trajectory; probe–goal arc + plaques; multi-parent sharing overlay; region/hull with edge marks; index-wise correspondence map; joint hub figure; competition gate; violation marks; realization plate; ordered chain path), drawn from the plates/lab designs through the §6 gates.
   - **Per-mark licensing map:** for every mark the grammar draws, the exact authored field(s) that license it (arrowhead ← the entry's approved notation for the recognized relation over its `source`→`landing`/ordered witnesses; plaque row ← a named `values` key; parent-edges ← each `parents` witness; violation mark ← the recognized violation relation identity plus its authored status role). Render provenance records, per mark: registry entry ID + version, the relation instance, and the licensing fields — so every meaningful visual is auditable to its authored source.
   - **Graceful degradation:** strict signature validation; a relation matching an entry's identity but **missing required roles** gets no specialized rendering (it takes the §4 fallback, and the inspector states which required roles were absent); optional-role marks simply drop when their roles are absent; nothing is ever guessed, defaulted, or filled from context.
3. **The styling layer** — a separate, also-versioned table of aesthetic parameters (curve tension, palettes, typography, lens grouping under the Lens Rule) applied *within* whatever grammar (specialized or fallback) is already licensed. Styling can never add, remove, or redirect a semantic mark.
4. **Always-available literal displays** (registry-independent, safe for any relation): witness highlighting; `values` rows rendered verbatim; π ghosting of authored silence; ι shared indices (identity display only — ι alone never draws a dependency [SETTLED]); authored-order ordinal badges (numbers, never arrowheads); the unregistered-relation presentation of §4; stage-timing badges (labeled derived).

**What this architecture prevents and preserves:** prevented — prose/label/ID/similarity inference; partial name matches; guessed anchors; drawings for unrecognized names beyond the fallback; any mark without a recorded authored license. Preserved — the open ontology (unrecognized relations are fully authored, stored, inspected, and fallback-rendered; the registry grows without bound through gates); the compiler-purge boundary (CA §8: the purge removed *inference of relations*; the registry renders *authored* relations — no conflict); complete rich derivations; Francis's sole visual authority.

**Contract dependencies:** entries whose signatures need only `anchors` (Movement, chains, Sharing, domains, intervention, operator–variable, control/binding dependencies) are implementable under the current contract once gated; entries whose signatures require relation information (valuation plaques, realization plates, correspondence maps beyond anchor-groups, status-bearing violation marks) additionally depend on CE-2's approval of the `values` candidate — recorded per entry.

## 4. The unregistered-relation fallback — delivered candidates; Francis selects [R10]

**What the inspected practice does** (corpus: the repo's 24 cached plates [PAGE-VERIFIED in-repo] plus the surveyed textbook/tool conventions of PROOF §5 — an inspected corpus, **not a field census**): when a relation has no dedicated drawing convention, this corpus does not draw connector networks — it **co-indexes the participants on the tree and states the relation off-tree** (subscript indices; numbered example lines; legends). No generic hub-and-spoke connector convention appears in the inspected corpus (a corpus observation; field-wide absence is not claimed); arcs are attested but not neutral here — in this visual culture an arc between tree nodes connotes movement/dependency, so defaulting arcs onto arbitrary relations (identity, mere association) would over-assert.

**Delivered candidates (each fully specifiable over the same architecture; the choice is pure visual craft):**

- **β — index-badge + relation panel (recommended; the "citation form").** Each unregistered relation instance gets a numbered badge (①, ②…) on every witness node plus a panel/legend entry — "① ⟨authored name⟩ — role: node…, key: value…" — with bidirectional selection-highlighting. Renders everything renderable: anchors (badged witnesses), roles (panel + hover labels), authored array order (ordinal positions and superscript marks — numbers, never arrowheads), `values` (verbatim panel rows), `priorAnchors` (badge in the previous stage's view + "from previous stage" note). Arity-uniform (unary/binary/n-ary identical mechanics); dense-tree legible (no edge clutter; >3 badges per node collapse to "+n", expandable); works in static Canopy (badges + panel below the tree — paper-like), Growth/Replay (badge appears at its authored stage; stage-scoped panel), workbench lenses (per-relation-name toggle groups), accessibility modes (shape+number badges, never color-only; plain-text panel; reduced motion), and export (badges and panel print). Deterministic geometry: badge order per node = (stage index, authoring order); panel order the same; selection priority = most recent selection, then stage order; collision = stack then collapse, never silent drop.
- **β+α** — badges + an **opt-in** neutral undirected arc for binary instances (off by default; serves users who want visible linkage without making the over-connoting form the default).
- **γ** — labeled undirected hub-and-spoke connectors (universal arity; culturally alien to syntax practice; clutter-prone in dense trees; retained as a candidate, demoted from recommendation).

**Invariants under every candidate:** no invented direction, identity, containment, scope, movement, failure, or causation — only authored content appears — decoded-string-exact names, roles, order, values, and witnesses (CA §5.1 fidelity layers); the reserved style is defined once in the legend as "authored relation without a curated visual convention," so a generic drawing **never impersonates a specialized convention**; renderer inability (overflow → declared "+n" state) is never conflated with invalid authored data (unresolvable anchors are upstream typed errors and are never rendered as valid); repeated/overlapping relations stay legible by stacking/collapse and panel completeness; every candidate works across Canopy, Growth, Replay, workbench, accessibility modes, and export. Until Francis selects, the candidates exist as design sheets and disposable prototypes only — never production code paths; production fallback implementation follows his selection (SP W11/W12 boundary) — the recommendation is β.

## 5. Multidominance and scope exclusions [SETTLED]

**Multidominance/sharing is a solved relation-layer case, not a contract counterexample.** The lab already authors and draws it: one shared object in the tree-shaped `workspaceForest`, an explicit sharing relation with `parents` anchors and a `shared` anchor, rendered by the Sharing lens (`visual-relations-lab-adapter.ts:215–221`; the lab's Sharing case [VERIFIED-CURRENT]). The registry's Sharing entry is that lens, gated. `workspaceForest` remains tree-shaped by design (the live serialization rationale, `systemInstruction.js:85` [VERIFIED-CURRENT], explains why the *forest* stays a tree while the *relation* expresses the sharing analysis). **No native DAG storage or structural refId-sharing mechanism is required or planned**; any future proposal to that effect must first demonstrate a concrete Babel requirement that the authored sharing relation cannot represent or draw — none is currently demonstrated. Register/matrix statuses are updated accordingly (PROOF: R07.01/R07.02 NOW via the relation layer; M2.T6 NOW).

**Plain scope exclusions, not artificial gaps:** prosodic objects, external speech-act participants, and unrelated framework-native non-tree structures (HPSG AVMs, LFG f-structures, TAG ports, RRG projections) are not objects Babel is intended to show in the syntax tree; they remain explicitly outside the visualization scope, stated as such per row in PROOF, with syntactic-witness fragments of such analyses representable through ordinary relations.

## 7. Fidelity property and adversarial obligations

Machine-checked, permanent: every semantic mark carries provenance (registry entry ID + version; relation instance; licensing fields); all displayed text is exact decoded authored string content or declared notation (raw bytes are preserved and hashed at the archive layer only — CA §5.1 fidelity layers); unrecognized names never receive specialized geometry; signature-incomplete matches degrade gracefully with the missing roles named; registry and styling versions are recorded per render; removing a registry entry removes exactly its grammar's marks (affected relations revert to the fallback) and nothing else. Adversarial fixtures: a misleading name with a non-matching signature → no match; a typo'd/unlisted name → fallback; identical anchors under `Movement` vs. an unrecognized name → arrows only for the recognized, signature-complete Movement; `Movement` missing `landing` → fallback with the missing role named; prose/label/ID variation over identical authored relations → identical rendering; a transition relation (`priorAnchors`) renders its boundary figure only via a gated entry, else two-sided badges with the prior-stage note; an unknown n-ary relation with `values` renders badges + role-labeled panel rows and no connector by default.

## 8. Contradiction audit (this document)

Specialized geometry requires recognized identity + validated signature — a rendering of authored commitments, never invention; unrecognized names keep the ontology open via the (Francis-open) fallback; prose/label/ID inference remains impossible by construction; ι alone never yields dependencies; multidominance is relation-layer-solved with no DAG requirement (the displayed object may show multiple mothers; storage stays a tree + relation); the fallback is a Francis selection among delivered candidates, never an arbitrary sketch declared approved; fixtures ≠ approval; Francis holds every gate; nothing here implements or promotes. Consistent with CA (contract untouched; purge boundary intact; CE-2 dependencies recorded per entry) and with SP (W11 builds the mechanism, fallback candidates, and literal displays with an empty registry; W12 populates entries through the gates).
